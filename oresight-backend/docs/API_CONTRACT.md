# OreSight API Contract

Generated by `scripts/export_contract.py` on 2026-09-05T14:56:27.899482+00:00 against the real seeded dev database. Every example response below is a genuine captured API call, not hand-written.

- **Base URL:** `http://localhost:8000`
- **CORS:** open for `http://localhost:5173, http://localhost:3000, http://127.0.0.1:5173`
- **Interactive docs:** `/docs` (Swagger UI), `/redoc`
- **Raw OpenAPI schema:** [`openapi.json`](openapi.json) (exported alongside this file)
- **Error envelope:** every error response (404, 409, 422, 400) includes an `error_code` field (`NOT_FOUND`, `CONFLICT`, `VALIDATION_ERROR`, `BAD_REQUEST`, ...) from a global exception handler in `app/main.py`. This applies to every endpoint, not just the ones showing it in an example below.
- **ID stability:** equipment/production/risk-event ids are autoincrements and are NOT stable across `scripts/rebuild_demo_db.py` reseeds — only `/demo/scenarios` keys are guaranteed stable across a rebuild. Examples in this doc reflect a single point-in-time capture; ids, counts, and timestamps will differ on a fresh capture.

## Shift Plan

Purely additive. A shift plan entry is a snapshot of one option from `GET /recommendations` that a planner chose to act on. `POST /shift-plan` stores one; `GET /shift-plan` lists a site's entries. No other route reads or writes `shift_plan_entries`. (Hand-maintained section; `scripts/export_contract.py` will fold these routes in on its next run.)

### POST `/shift-plan`

Add a recommendation option to the shift plan

**Query/path params:**

_None_

**Request body:**

- `risk_event_id` (`integer`, required) — the risk event the option was generated for
- `option_type` (`string`, required, one of `reschedule` | `redeploy` | `adjust_plan`)
- `description` (`string`, required, `minLength=1`)
- `target_id` (`string | null`, optional) — the blast plan / equipment id the option points at, when the caller has it
- `projected_impact` (`number`, required, `minimum=0`, `maximum=100`)
- `confidence` (`number`, required, `minimum=0`, `maximum=1`)

> `site_id` is NOT accepted in the body — it is taken from the referenced risk event and returned in the response.
>
> Unknown `risk_event_id` -> `404 {"detail": "Risk event <id> not found", "error_code": "NOT_FOUND"}`. An unknown `option_type`, or `projected_impact` / `confidence` out of range -> `422` with `error_code: "VALIDATION_ERROR"`. A write failure against a reachable database -> `502 {"detail": "Could not save the shift plan entry.", "error_code": "UPSTREAM_ERROR"}`; an unreachable database -> `503`.

**Example** - `POST /shift-plan` -> `201`

```json
{
  "id": 3,
  "risk_event_id": 5,
  "site_id": 2,
  "option_type": "redeploy",
  "description": "Redeploy Haul Truck HT-303 from Bhandara to Nagpur to cover Haul Truck HT-302.",
  "target_id": "eq_bhandara_06",
  "projected_impact": 77.0,
  "confidence": 0.8,
  "created_at": "2026-09-08T14:20:00Z"
}
```
